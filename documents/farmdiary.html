01담당 구현

유니티 엔진 기능만으로는 만들 수 없는 "바탕화면 위에서 돌아가는 게임"을 위해, 운영체제 API를 직접 연동한 작업이 중심입니다.

1.Windows API 기반 투명 오버레이 시스템

  • user32.dll, dwmapi.dll을 연동해 바탕화면 위에서 실행되는 투명 윈도우 환경 구축
  • Raycast로 포인터 위치를 판별해 UI 밖의 클릭은 바탕화면으로 통과(Click-Through)
  • 백그라운드 실행과 최상단 고정으로 데스크톱 위젯 같은 UX 제공

결과기존 게임 실행 방식과 차별화된, 다른 작업과 병행하는 멀티태스킹 환경 구현

2.OS 레벨 키보드 후킹 시스템

  • SetWindowsHookEx로 게임 창이 비활성 상태여도 키 입력을 감지
  • 입력 데이터를 업적 · 재화 시스템과 연동
  • UnhookWindowsHookEx로 후크를 해제해 안정성 확보

결과게임 밖의 행동(타이핑)까지 게임 진행으로 확장할 수 있는 구조 확보

3.FSM 기반 자동화 농사 AI

  • 행동 단위를 상태(State)로 분리해 설계
  • 작물 상태 데이터에 따라 자동으로 상태 전이

결과기능을 추가할 때 기존 코드를 수정하지 않고 상태만 추가해 확장 가능

4.카메라 · UI 동적 대응

  • 줌 레벨에 따라 UI 위치와 크기 자동 조정
  • 극단적인 화면 배율에서도 UI 가독성 유지

결과다양한 해상도와 상황에서 일관된 사용자 경험 유지

02핵심 코드

투명 창의 핵심은 "언제 클릭을 받고, 언제 바탕화면으로 흘려보낼지"입니다. 포인터가 게임 UI 위에 있는지에 따라 윈도우 확장 스타일을 바꿔, 게임과 바탕화면을 동시에 쓸 수 있게 했습니다.

  • 창 핸들 검증 — GetUnityWindowHandle()이 실패하면 즉시 반환해 잘못된 핸들로 Win32 API를 호출하지 않도록 방어
  • 스타일 조합 — 항상 WS_EX_LAYERED를 유지한 채 WS_EX_TRANSPARENT만 붙였다 떼어, 투명 렌더링은 유지하면서 입력만 전환

03문제 해결

빌드하면 투명해야 할 배경이 검은 화면으로 출력

문제
Windows API로 투명 오버레이를 적용했지만, 빌드한 게임에서 배경이 투명하지 않고 검은 화면으로 출력
추적
약 4~5일간 원인을 추적하며 URP 렌더링 구조까지 분석
원인
URP 카메라의 HDR이 켜져 있으면 알파 채널이 없는 HDR 컬러 버퍼 포맷으로 렌더링되어, 투명도(알파) 정보가 창에 전달되지 않음
해결
카메라의 HDR 옵션을 끄고 빌드
결과
빌드 환경에서 투명 백그라운드가 정상 적용
