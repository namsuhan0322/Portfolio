01담당 구현

팀장이자 메인 프로그래머로 전투 구조를 설계하고, 로딩 · 저장처럼 플레이어가 직접 의식하지 않는 부분의 체감 품질을 개선했습니다.

1.Action 델리게이트 기반 Actor & 전투 아키텍처

  • OnDeath, OnHPChanged, OnStun 등 이벤트(Observer) 패턴으로 클래스 간 결합도 최소화
  • 강인도(Poise) 시스템과 타이머 기반 무적(I-Frame) 등 소울라이크 핵심 전투 기믹 설계

결과유지보수와 확장이 쉬운 전투 시스템 구축, 타격감 있는 전투 템포 완성

2.비동기 씬 로딩 최적화 및 동적 로딩 UX

  • allowSceneActivation 전환 시 발생하는 메인 스레드 프리징을 99% Creeping 로딩 연출로 가림
  • 구조체(Struct)로 이동할 씬에 맞는 팁(Lore)과 일러스트를 로딩 화면에 동적으로 주입

결과읽기 병목 구간을 부드러운 연출로 감춰 로딩 체감 개선

3.파일 I/O 병목 최적화

  • 대량 아이템 획득 시 반복 호출되던 Auto-Save 로직에 저장 여부 플래그 도입

결과대량 지급 시 디스크 저장을 한 번으로 줄여 프레임 드랍 해결 (아래 문제 해결 참고)

02핵심 코드

유니티 비동기 로딩은 마지막에 씬을 활성화하는 순간 메인 스레드가 멈춥니다. 이 구간에 진행률이 멈춰 있으면 플레이어는 게임이 멈춘 것처럼 느끼기 때문에, 숫자가 99%까지 천천히 차오르는 연출을 먼저 보여주고 그 뒤에 활성화하도록 순서를 바꿨습니다.

  • unscaledDeltaTime 사용 — 일시정지 등으로 Time.timeScale이 0이어도 로딩 연출이 멈추지 않음
  • 메모리 선정리 — 새 씬을 읽기 전에 GC.Collect()와 UnloadUnusedAssets()로 이전 씬의 미사용 리소스를 해제
  • 100%의 의미 — 씬 활성화와 첫 렌더링이 끝난 뒤에만 100%를 표시해, 숫자와 실제 상태를 일치시킴

03문제 해결

대량 아이템 획득 시 심각한 프레임 드랍

문제
아이템 · 재화를 획득할 때마다 즉시 저장하는 구조라, 테스트 환경이나 보상 대량 획득 시 짧은 프레임 안에 디스크 쓰기(SaveAllData)가 7번 이상 연속 발생
해결
InventoryManager의 획득 함수에 bool autoSave = true 매개변수를 추가해 단일 획득과 대량 획득의 저장 로직을 분리. 대량 지급 시에는 false로 넘기고, 모든 처리가 끝난 뒤 마지막에 한 번만 저장
결과
대량 지급 시 디스크 저장이 7회 이상 → 1회로 줄어 프레임 드랍 해소, 씬 전환과 대규모 데이터 처리 시 병목 해결
